# M1 架构：FR 产品壳与环境注册模型

## 1. 本阶段交付

M1 将上游桌面程序变成独立的 **FR ComfyUI Control Center** 产品壳，但不创建、升级或接管任何 ComfyUI 环境。核心成果分为四层：

1. 独立产品身份：名称、图标、窗口标题、安装包标识和应用数据目录。
2. 非技术首页：现有实例的启动/管理入口，以及 stable、next、lab 三张环境卡片。
3. 环境注册模型：未注册、只读、受管三种状态，以及 stable/next/lab 角色约束。
4. 安全边界：没有 FR 更新渠道时关闭自更新，没有 FR 遥测渠道时关闭上游遥测；建议路径不自动探测。

## 2. 产品身份与数据隔离

| 项目 | M1 值 | 说明 |
| --- | --- | --- |
| 产品名 | `FR ComfyUI Control Center` | 窗口、安装包和可执行文件统一使用 |
| 包名 | `fr-comfyui-control-center` | 与上游包名分离 |
| Windows App ID | `ai.fr.comfyui.controlcenter` | 与上游安装身份分离 |
| Windows 应用数据 | `%APPDATA%\FR-ComfyUI-ControlCenter` | 设置、安装记录、环境注册表和日志的 FR 专属根目录 |
| 安装包 | `FR-ComfyUI-ControlCenter-<version>-win-x64.exe` | 不再生成官方品牌文件名 |
| 图标 | `assets/FR_ControlCenter.svg` 及派生 PNG | FR 原创源文件，可重复生成各尺寸 |

身份配置在主进程其他模块加载前完成，避免设置、令牌或分区模块先解析到上游用户目录。E2E 使用显式临时 userData，不读取真实用户资料。

上游兼容格式不会为了改名而破坏。例如历史快照类型和安装侧 `.comfyui-desktop-2` 标记仍保持兼容；它们是数据协议，不是 FR 应用数据目录，也不代表自动接管现有环境。

## 3. 三环境角色

| 角色 | 建议路径 | 责任 | M1 行为 |
| --- | --- | --- | --- |
| stable | `C:\FR_comfyui` | 用户现有稳定基线和最终回退 | 只显示建议；明确注册前不读取 |
| next | `C:\FR_comfyui_next` | 未来的新技术主环境 | 只显示建议；M1 不创建 |
| lab | `C:\FR_comfyui_lab` | 重大 Python/Torch/CUDA/模型实验 | 只显示建议；M1 不创建 |

`C:\FR_comfyui_cache` 是未来 FR 自有下载、wheel、编译与清单缓存，不是一个可启动环境；M1 同样不创建。

三种注册状态：

| 状态 | 控制中心可做什么 | 控制中心不可做什么 |
| --- | --- | --- |
| 未注册 | 显示角色、建议路径和说明 | 不 `stat`、不扫描、不创建、不判断健康 |
| 只读 | 记录用户选择的目录；读取目录是否存在 | 不更新、不修复、不迁移、不写入目标目录 |
| 受管 | 记录用户明确授权及时间，为后续事务提供权限依据 | M1 仍不写目标目录；M2+ 的每次变更仍需预检、日志和恢复点 |

同一个物理目录不能同时注册为两个角色。Windows 路径按大小写不敏感规则做碰撞检查。断开注册只删除 FR 自己的注册记录，不删除目标目录。

注册表保存为 FR userData 下的 `fr-environments.json`，采用安全文件写入与备份恢复；如果主文件不可读，系统失败关闭写入，避免用旧备份覆盖较新的数据。

## 4. 首页和操作语义

首页面向普通用户，已有安装实例提供：

- 启动/打开：沿用经过验证的实例启动流程。
- 更新：打开该实例的管理页，不在首页直接执行更新。
- 检查与修复：打开诊断/修复入口，不在首页静默修改依赖。
- 回退：打开快照页，不在首页直接恢复快照。

环境卡片提供显式的“只读注册”和“纳入管理”选择。受管模式必须经过确认提示，说明 M1 只记录授权，不会立刻改变目录。

因此 M1 首页是安全入口层，不是绕过快照和事务保护的快捷执行器。

## 5. 更新、遥测与上游边界

- FR 尚未配置用户自有更新源，因此应用自更新能力以“渠道未配置”状态失败关闭，不连接上游 Desktop 发布渠道。
- FR 尚未配置用户自有遥测后端，因此主进程 PostHog 和渲染进程 Datadog 通道均关闭。
- GitHub 设置卡片明确标记为“Upstream Comfy Desktop”，仅用于来源追踪。
- Manager、ComfyUI Core、Python/Torch 和自定义节点的版本策略均未在 M1 改写；它们分别属于 M2、M3、M5/M6。

## 6. M2 的输入边界

M2 可以消费 M1 的角色、路径、模式和授权时间，但不能把“受管”解释成无限授权。每个创建或修改事务仍必须：

1. 生成 dry-run 计划；
2. 检查目录、磁盘、权限、长路径和链接能力；
3. 明确列出将写入的目标；
4. 建立日志和恢复方案；
5. 经用户触发后才执行。

共享模型库 `C:\FR_comfyui\models` 的扫描和映射属于 M4；在此之前不创建链接、不改 `extra_model_paths.yaml`、不整理模型文件。
