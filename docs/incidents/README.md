## 以后怎样记录

每次新增或补充故障记录时：

1. 先保留现场：日期、环境和程序版本、插件路径与提交、相关日志/截图、实际变更文件。
2. 区分已确认原因、推断和待确认项，记录能复现问题的最小证据。
3. 写清改了什么、保留了哪些保护，以及实际修改到源码、构建产物、安装包、已安装文件中的哪一层。
4. 列出已经执行的验证及其范围；历史测试轮次不能简单相加作为总覆盖量。
5. 保存本机变更前备份、目标路径、前后哈希及回滚前置条件；多次补丁写清回滚顺序。
6. 把通用教训补入相关开发说明和 `AGENTS.md`；新增本索引入口。

本目录的 Markdown 和 `docs/evidence/` 的结构化结果适合随源码保留。
`artifacts/` 中的截图、原文件和事务清单是本机取证及恢复材料，不能因整理记录而删除。
该目录已由 Git 和 ESLint 忽略，保留在本机，不随源码提交和推送；详细记录中的相关链接供本地查阅。
本机路径和哈希用于审计；不要把密码、令牌、证书私钥或完整用户配置写进记录。
