# M8 恢复、迁移与卸载手册

## 1. 不可破坏的边界

- `C:\FR_comfyui` 始终是用户现有稳定环境；控制中心不得更新、修复、重命名、迁移或删除它。
- `C:\FR_comfyui\models` 是共享模型库；恢复、迁移和卸载都不得移动、复制、重写或删除其中的模型。
- next、lab、cache 只有在存在 FR 所有权标记且 dry-run 精确列出目标时，才允许进入清理计划。
- Python、`custom_nodes`、Manager 状态、用户配置和编译缓存不在环境之间复制。

## 2. 故障恢复顺序

1. 停止发生故障的 next 或 lab 环境，不启动稳定环境以外的并行修复进程。
2. 收集本次事务日志、版本清单、硬件探针和失败阶段，不先修改现场。
3. 核对事务开始前的已提交快照或恢复点；没有恢复点时停止自动恢复。
4. 只恢复受影响的层：runtime、Core、frontend、Manager、插件或模型映射，禁止顺带升级其他层。
5. 重新执行导入、启动、Manager v4 API、GPU/attention 和代表性工作流检查。
6. 检查失败则撤销目标层并保留日志；稳定环境继续作为独立回退入口。

## 3. 各层回退策略

| 层 | 恢复单位 | 失败后的处理 |
| --- | --- | --- |
| Python/Torch 运行时 | 完整 runtime 目录 | 原子切回上一完整目录，不在原目录内混装 wheel |
| ComfyUI Core | 离线 Git bundle 和锁定提交 | 恢复旧提交与干净工作树，再跑启动探针 |
| frontend | 锁定包版本 | 只回退 frontend 包并重建应用 |
| Manager v4 | 包版本和每环境 `config.ini` | 恢复 v4 包与配置，复测 `/api/v2`；不使用 v3 布局 |
| 自定义节点 | 插件快照和逐插件事务 | 回退当前插件；未验证插件继续隔离 |
| 模型映射 | YAML 和撤销清单 | 恢复映射元数据；不改模型文件 |

## 4. 旧环境迁移

默认模式是“只读登记”：记录旧环境位置和版本，仅用于展示与启动，不纳入自动更新。

可选“复制到 next”必须先满足：源环境存在且已停止、目标缺失或带 FR 所有权标记、目标有恢复点、所有根目录互不重叠。迁移只把经过选择的工作流与用户配置放入 staging，模型通过映射引用，插件按审核结果重新干净安装。验证通过后才原子发布 staging；失败只撤销目标，源环境保持原样。

## 5. 卸载和数据清理

卸载控制中心默认保留 stable、next、lab、cache 和共享模型。用户另行选择“删除 FR 管理数据”时，控制中心必须先显示 dry-run，只允许列出有 FR 所有权标记的 next、lab、cache；任何未标记目录都会令事务阻断。稳定环境和共享模型库在所有模式下都是硬保护目标。

应用安装包的卸载仅移除控制中心程序本身，不代表授权删除 ComfyUI 环境或模型数据。
